after a change of shape**. Rule set `zealand-local-plans-v2`, unchanged since
[`baseline-2026-08-29.md`](baseline-2026-08-29.md). Committed once, never

prompt-fixable?** It is. The number is back above its v1 level.

### What the fix actually was

Two changes, one per finding in the 2026-08-29 document.

**1. The citation failure was prompt-side, and the fix is a prompt version.**
The model was paraphrasing its citation ("as documented in the plan PDF")
rather than quoting the doklink, systematically, on the short R3 summaries
that rule-set v2 newly routes to `file`. The repair adds two numbered,
non-negotiable requirements to the `summarise` system prompt: state the
before and after values of at least one changed field, and end with the
source URL copied character for character, never replaced by a description.

Measured at **1.000 across two full independent passes** before being
promoted, then 1.000 again in this baseline run — three passes in total, no
failures in any of them. The previous failure was systematic (7 of 8 cases
failing in all three passes), so its complete disappearance across three
passes is a real repair rather than run-to-run wobble.

**2. `no_invented_numbers` was a scorer bug, not a model fabrication.** The
2026-08-29 document judged this correctly and this run confirms it: `ZL-025`
and `ZL-027` are named `"Delområde 2"` / `"Delområde 3"`, and
`_context_numbers` only allowed a *bare* numeric sub-area code like `"3B"`,
so the digit inside the Danish label read as an invented figure. Naming the
sub-area you were handed is faithful citation. `evals/scorers.py` now also
extracts digits embedded in those string fields, and
`tests/test_scorers.py` pins both directions — the label digit is allowed,
and a genuinely fabricated number alongside it still fails.

### On the prompt source

`--no-langfuse` strips the Langfuse keys, so both prompts resolve to their
**pinned local fallback** in this run. That is deliberate and worth stating
plainly: the number above is produced by text committed in this repo
(`llm/prompts.py`'s `FALLBACKS`), not by a value fetched from a vendor whose
free tier deletes data after 30 days. The registry copy is byte-identical —
`push_fallbacks()` seeds Langfuse *from* those constants, so v2 in the
registry and the fallback here are the same text by construction.

## What this run also establishes

- **The gate now has numbers to enforce.** `evals/thresholds.json` is set from
  this run: 0.96 floors on the wobble-prone scorers (one case in 27 may fail
  without failing CI), 1.000 on the two deterministic ones. `evals/gate.py`
  was verified in both directions — exit 0 on this run's aggregate, exit 1 on
  the 2026-08-29 citation numbers replayed through it.
- **Prompt versions are now recorded on every baseline** (`resolved_prompts`
  in the JSON output, alongside `resolved_models`). A score is only
  comparable against another score whose prompt version is also known.

## What this does not measure

Same scope as the two previous baselines — see `baseline-2026-08-22.md`'s
"What this does not measure" for the full list. Two notes specific to this
document:

- **Cost went up 53% and that is not free.** The longer prompt buys the
  citation guarantee; at the volume R3 implies in the wild, that trade should
  be revisited with a cheaper model rather than assumed permanent.
- **Three passes is not a determinism proof.** `temperature=0` is not a
  guarantee on a hosted MoE endpoint (`baseline-2026-08-22.md`'s `ZL-018`
  finding), which is exactly why the committed thresholds sit at 0.96 rather
  than 1.000 for the prose scorers.
