## The headline finding: `citation_fidelity` dropped from 90.5–100% to ~70–74%, systematically

This is a real regression against v1, and it is not the same shape as v1's
`ZL-018` finding. v1's citation failure was **intermittent** - one case,
passing in some stability passes and failing in others, consistent with
`temperature=0` not being a determinism guarantee on a hosted MoE endpoint.

v2's failure is **systematic**: across all three stability passes, 7 of 8
distinct failing case ids failed in every single pass (`ZL-004`, `ZL-023`,
`ZL-025`, `ZL-026`, `ZL-027`, `ZL-028`, `ZL-029` - 3/3 each; `ZL-024` failed
1/3). Inspecting the model's actual output for two of these
(`ZL-024`, a passing example, versus `ZL-004` and `ZL-023`, both consistently
failing) shows why:

- `ZL-024` (passes): "...(source:
  `https://dokument.plandata.dk/20_3744192_1520336144071.pdf`)." - the
  doklink appears verbatim.
- `ZL-004` (fails): "...as documented in the plan PDF." - the model
  paraphrases the citation instead of quoting the URL.
- `ZL-023` (fails): ends without citing the source URL at all.

This is the same `summarise()` function and the same `SYSTEM_PROMPT` as the
v1 baseline used - nothing in the prompt changed for rule-set v2. What changed
is which cases now reach `summarise()` at all: six of the seven consistently-
failing cases (`ZL-024`–`ZL-029`, the R3 additions) are cases that under v1
never called the model - they were rule-decided `ignore` and produced no
output text to score. v2 files them, so this baseline is the first time their
prose has ever been measured, and it is finding that the model is
substantially less reliable at citing its source verbatim for this case shape
(a field gaining a value, described in a single short sentence) than for the
longer, more consequential-reading cases (a use change, a dimensional limit
change) that made up most of v1's `file` population.

**This is the most significant finding in this baseline, not a rounding
error.** `citation_fidelity` is the project's one rule, tested mechanically.
A prompt or scorer fix is warranted before this rule set's `file` path should
be trusted unattended at the volume R3 now implies (R3-style cases are the
single most common shape in the wild - see `evals/golden/README.md`).

## `no_invented_numbers`: a stable, narrower finding

`ZL-025` and `ZL-027` fail in every pass. Both sub-areas are named
`"Delområde 2"` / `"Delområde 3"` in their `source.sub_area` field; the
model's output states that number as part of the area name, and the scorer's
`_context_numbers` allowance for `source.sub_area` only covers a bare numeric
sub-area code (e.g. `"3B"`), not a digit embedded inside a longer Danish label
like "Delområde 2". This reads as a scorer boundary gap rather than a model
fabrication - worth a scorer fix, not a prompt fix, and much narrower in
consequence than the citation finding above.
