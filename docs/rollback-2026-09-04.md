# Rollback, executed: 2026-09-04

Not "rollback is possible". A rollback of the production prompt was executed
against the live registry, timed, and verified by reading back what the agent
actually serves.

Reproduces via `uv run python -m tilsynsagent.llm.rollback <prompt-name> --to <version>`.

## What was rolled back

`tilsynsagent-summarise-system`, from **v2 to v1**.

This is a meaningful rollback rather than a staged one: v2 is the prompt that
repaired the citation-fidelity regression (`citation_fidelity` 0.704 -> 1.000,
see [`evals/baseline-2026-09-04.md`](evals/baseline-2026-09-04.md)), and v1 is
the text that produced the regression. Rolling back genuinely reverts a
behaviour fix, so "did it take effect" has an observable answer rather than
being a matter of trusting the log line.

## The measurement

| | |
|---|---|
| v2 -> v1 (roll back) | **0.09 s**, verified |
| v1 -> v2 (roll forward) | **0.15 s**, verified |
| Worst case until every running process has it | **~60 s** |
| Code deployed | none |
| Processes restarted | none |

**The two numbers are both reported on purpose.** The label move is
near-instant. What a caller actually experiences is bounded by
`prompts.CACHE_TTL_SECONDS` (60 s), because a process already running serves
its cached copy until that expires. Publishing only "0.09 seconds" would be
true and misleading, so `RollbackResult` computes and states both, and
`tests/test_rollback.py` pins that it does.

## How it was verified

Timing a label move proves nothing on its own — a rollback that is fast but
did not take effect is not a fast rollback. Two checks, in order:

1. The version the `production` label resolves to was read back **uncached**
   (`cache_ttl_seconds=0`), and matched the requested version.
2. The prompt the agent actually serves was fetched through the normal
   `get_prompt()` path and inspected for v2's distinguishing text
   ("character for character"). After the rollback: absent, serving v1. After
   the roll-forward: present, serving v2.

An unverified rollback is reported as `NOT VERIFIED` and exits non-zero rather
than printing a time.

## Why this is a label move and not a deploy

The production prompt is whatever version carries the `production` label (see
`llm/prompts.py`). That is the entire argument for a prompt registry: a prompt
edit changes behaviour as much as a code change does, but shipping the fix —
or undoing it — should not require shipping code. The measured difference is
0.09 seconds against a deploy cycle.

## What this does not cover

- **A rollback under load.** This was executed against an idle system. The
  60 s propagation bound is arithmetic from the cache TTL, not an observed
  worst case with concurrent runs in flight.
- **Config other than prompts.** Rule-set and model selection are still code
  and environment changes, and reverting either is a deploy.
- **Automatic rollback.** The trigger here is a person deciding. The drift
  detector (`obs/drift.py`) can say *degraded*; nothing yet acts on that
  without a human.
